PHASE 0 · TRIGGER
STEP 00
⚡
Alert / Phishing Email Reported
Investigation is triggered by one of the following sources:
User Report
  • Employee forwards suspicious email to security mailbox
Gateway Alert
  • Email security tool flags and quarantines message
SIEM / Threat Intel
  • IOC match or anomaly detection triggers alert
PHASE 1 · OBTAIN
STEP 01
📥
Retrieve Original Email Copy
Always obtain the raw email file — never rely on previews or forwarded copies which strip headers.
Email Gateway
  • Pull directly from gateway quarantine or logs
Mail Server
  • Extract from Microsoft Exchange or similar
User-Forwarded
  • User forwards as attachment (preserves headers)
⚠ OPEN EMAIL ONLY IN A VM OR DEDICATED "DIRTY" ANALYSIS SYSTEM
PHASE 2 · INITIAL IDENTIFICATION
STEP 02
🔍
Identify Phishing Indicators
Perform a rapid first pass to confirm the email is suspicious and understand the attack type.
Common Red Flags
  • Unknown / spoofed sending address
  • Urgency language or emotional pressure
  • Grammar errors / poor formatting
  • Mismatched display name vs actual address
  • Unexpected attachment or link
  • Sender domain ≠ claimed brand domain
Attack Type Classification
  • Credential Harvester — fake login page
  • Malware Delivery — malicious attachment
  • BEC — impersonates executive/vendor
  • Social Engineering — info extraction
  • Spear Phishing — targeted individual
Open in Text Editor Email Client (Thunderbird) VM Only!
PHASE 3 · ARTIFACT COLLECTION
STEP 03
🗂
Collect All Artifacts (IOCs)
Extract all email, web, and file artifacts before proceeding to analysis. Use a text editor on the raw .eml file.
📧 Email Artifacts
  • Sending Address (From)
  • Sending Domain
  • Reply-To (if different)
  • Date & Time
  • Subject Line
  • Sending Server IP (X-Sender-IP)
  • Reverse DNS of sending IP
  • SPF / DKIM / DMARC result
🌐 Web Artifacts
  • All URLs in email body
  • Hyperlinks in HTML anchor tags
  • Shortened URLs (expand safely)
  • Redirect chain destination
  • URLs inside attachments
📁 File Artifacts
  • Attachment filename + extension
  • File size
  • MD5 hash
  • SHA256 hash
  • Base64-encoded body content
Text Editor (.eml) CyberChef (Base64 decode) PowerShell Get-FileHash sha256sum (Linux) Document ALL values
PHASE 4 · ARTIFACT ANALYSIS
STEP 04
🔬
Analyze All Artifacts
Use tools to determine maliciousness. Treat artifacts as guilty until proven innocent.
📧 Email Header Analysis
  • Verify SPF / DKIM / DMARC pass
  • Check Reply-To ≠ From (spoofing?)
  • Trace Received headers (hop path)
  • Cross-check sending IP vs claimed domain
  • Look for X-Originating-IP anomalies
🌐 URL Analysis
  • Expand shortened URLs (WannaBrowser)
  • Screenshot site (URL2PNG / URLScan)
  • Reputation check (VirusTotal / URLScan)
  • Domain WHOIS (whois.domaintools.com)
  • IP reputation (IPVoid)
  • Check PhishTank / URLhaus feeds
📁 File Analysis
  • Hash lookup: VirusTotal / Talos
  • Upload file to VirusTotal sandbox
  • Manual analysis in VM (run safely)
  • Check macro presence (Office docs)
  • Enterprise sandbox (Cuckoo, etc.)
  • Watch for double extensions (.pdf.exe)
VirusTotal URLScan.io URL2PNG WannaBrowser IPVoid Talos File Reputation PhishTank MXToolbox Not flagged ≠ safe!
DECISION POINT
MALICIOUS?
ASSESS EVIDENCE
✗ NOT MALICIOUS
Close Ticket
Document findings. Mark as false positive. Inform reporter. No defensive action required.
✓ CONFIRMED MALICIOUS
Continue ↓
Proceed through remaining response steps immediately.
PHASE 5 · NOTIFY RECIPIENTS
STEP 05
📢
Inform All Email Recipients
Reduce the risk of interaction. Do not wait until defensive measures are complete.
How to Find Recipients
  • Check email gateway delivery logs
  • Query mail server for all recipients of the message-ID
  • Check To / CC fields in original email
Notification Must Include
  • Date & time the phishing email was sent
  • Subject line (to help them find it)
  • Clear instruction: DELETE or forward to security mailbox
  • Security team contact details
Send via BCC to all recipients Ask if anyone interacted with the email
PHASE 6 · DEFENSIVE MEASURES
STEP 06
🛡
Take Defensive Measures
Block artifacts at appropriate control points. Always assess business impact before blocking. Document every action with timestamp and analyst name.
📧 Email Gateway
  • Block Sender Address (if unique malicious)
  • Block Sender Domain (if fully malicious)
  • Block Sending Server IP (if not shared/legit)
  • Block Subject Line (if highly specific)
  • Recall delivered messages if possible
🌐 Web Proxy / Firewall
  • Block malicious URL
  • Block malicious domain entirely
  • Block redirect destination
  • Block shortened URL if not expandable
🖥 Endpoint / AV / EDR
  • Block file hash (MD5 / SHA256)
  • Quarantine or remove on infected hosts
  • Isolate infected machines if needed
  • Escalate to Tier 2 / IR if active compromise
⚠ ALWAYS ASSESS NEGATIVE BUSINESS IMPACT BEFORE BLOCKING — document your justification for EVERY action taken.
Record: Block Type · Value · Date/Time · Analyst Name
PHASE 7 · INVESTIGATION REPORT
STEP 07
📝
Write Investigation Report
Document every finding and action taken. This provides an audit trail and enables threat intelligence sharing.
Report Must Include
  • Executive summary of the attack
  • Complete IOC list (defanged)
  • Analysis findings for each artifact
  • Recipients notified and response
  • All defensive actions taken + justification
  • Timestamps for every action
  • Analyst name (accountability)
Defang All IOCs Before Publishing
  • 8.8.8.8 → 8[.]8[.]8[.]8
  • https://evil.com → hxxps://evil[.]com
  • Use CyberChef: Defang IP / Defang URL operations
  • Never leave clickable malicious links in reports
CyberChef (defang) Defang ALL URLs and IPs Log Block Type · Value · Date · Analyst
✔
Investigation Complete — Close Ticket
Archive report. Share IOCs with threat intel if applicable. Recommend user awareness training if users were compromised.
